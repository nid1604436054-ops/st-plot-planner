# 设计文档：产品理念与领域模型

> 本文是剧情规划器的「意图源头」：每个核心概念的身份、边界、消费者与生命周期都记在这。
> 材料 = 产品作者 2026-08-25 的口述草稿与三轮问答（桌面「简单的开发者文档草稿.txt」「依次来回答你的12个问题.txt」「4题.txt」）。
>
> 使用约定：
> - **动任何功能之前先重读本文**。与本模型冲突的实现改动，先改本文再动代码，概念级变更与代码走同一提交。
> - 普通功能改动不进本文，只进 DEVELOPMENT_PLAN §12 变更日志。
> - 条目分两栏：【实战】= 真实聊天里验证过；【意图】= 设计意图待验证。本插件至今只经历过约 12 小时开发、零实战浸泡，**当前几乎全部条目在【意图】栏**——跑完第一次完整战役与首次三千层大修后逐条回填（见 §7 台账）。

## 1. 这个产品是什么

一句话：坐在角色扮演聊天之上的**剧情守护层**——替扮演模型记住该记的、看见该看的，替作者管住剧情的方向与质量。

作者原话（产品的全部出发点）：

> 「我在酒馆玩角色扮演……都是在模型的设定和智力内让它更好的扮演角色，更接近真实，更像人，创造出更精彩的剧情。」

三个具体目的（作者原话）：**管理文件、提纯提示词、让扮演更加贴合。**

为什么需要它（作者的全知视角论，三个工具共同的存在理由）：

> 「过去的时间就是过去了，我参与的事情没必要再讨论，我没推动的事情不存在，角色不会自己发生我不知道的事情——换句话说，我是全知的。哪怕约会一千次，约会的流程也只取决于模型固定的创造力，而不会有新的变化。」

RP 的世界里没有「镜头外发生的事」，一切新鲜感必须被显式制造——这是随机事件、路人反应、剧情规划三个工具的立身之本。

## 2. 核心概念

### 2.1 一行记忆 = 对角色行为有影响的事件

不是「一条记录」。判断一行记忆价值的标准只有一个：**它会不会改变角色接下来的行为**。镜像、打标、召回的一切设计都为这个标准服务。

### 2.2 双读者模型：原表与镜像

插件里有两位读者，各看各的数据，**分叉是有意的**：

- **扮演模型**（主对话）看**原表**——记忆增强表格插件的数据；
- **规划/检查模型**（本插件的规划向导、检查报告）看**镜像**——本插件按聊天维护的副本。

镜像的定位是**规划侧的策展层**：删掉对规划无意义的表（时空记录表、物品表等每轮更新的噪音），让规划模型注意力集中、降本增效。作者原话：「我给扮演模型看的内容和我给规划模型看的内容可以不一样。」

- 日常操作以**删**为主；
- **改单元格**基本不用但保留——它是双读者差异的具象化（有些扮演要注意的细节，规划不需要落实）；
- 边界要说破：镜像里删一行，扮演模型照样「记得」这件事；**修扮演侧的事实只能去源插件改**。本插件对原表唯一的写路径是备份恢复（只增不改）。

### 2.3 行的身份 = 内容指纹

镜像行的身份 rid = hash(表uid + 列名 + 内容)。这是自然键身份：**内容一变，身份即换**——被改写的行会以「新行」姿态重新进来，旧标签、已读标记、删除墓碑都认不出它。

- 日常修正只发生在表尾两三行（最新进展），指纹漂移影响的只是本来就在变动的行。【实战：这是作者长期使用源插件的真实习惯，先于本插件存在】
- **大修**（每约三千层一次）：合并改写压缩 + 删旧行，覆盖近三千层新增内容。指纹雪崩（标签作废、墓碑失效、满屏新行）在这个场景**真实会发生**。作者接受代价并把处置纳入大修流程本身：**大修后人工核验一遍 + AI 重新打标**。这是标准流程，不是技术债。【意图：大修流程从未实跑过】

### 2.4 口径：这次给模型带哪些记忆

默认答案（作者原话）：「**越是贴合角色的越要，越是无关的越舍。**」相关性三要素：出场角色、剧情合理不重复、前进方向。

- 单主角卡：全量输入（完整关系成长经历贴合扮演）；
- 群像卡（如十人卡）：**名字标签 + 事件类型标签**组合筛（为此移除过单行 3 标签上限）。

口径是**两层模型**，各管各的：

| 层 | 位置 | 管什么 |
|---|---|---|
| 全局默认层 | 记忆表格页（每表一份） | **召回列**——剔除「角色名/备注」类对模型无用的列（列要留着给源插件显示，只在召回时剔除） |
| 单次覆盖层 | 向导第 1 步 | 表勾选 + 三档位（停用/按标签/常驻全量）+ 标签 + 表尾最新 N 行 |

- 「参与召回」总开关已判多余（向导勾选足够）→ T6 退役；
- **检查报告口径（已决）**：第四步检查**继承向导第 1 步**的表/标签选择——单人卡全量无感；群像卡只查同类事件重复、无关事件不计入；兜底 = 写指导意见打回。

### 2.5 三工具模型：规划 / 随机事件 / 路人反应

三者不是流水线，是**工具箱**：

- **随机事件**与**路人反应** = 对等的并行工具（作者原话「不是附庸品」），随时单独取用；
- **规划** = 「有多次重试机会的个性定制思维链」——**只规划不扮演**，让规划模型与扮演模型各自能力最大化。

**单元制**（互相干涉的正解；2026-08-25 定稿，取代早期「自动对称读取」草案——作者要控制权，不要自动）：两个现场工具的产物 = **单元**（暂存态，每工具名下 ≤3，满了禁止再生成、先手动删）。生成任一工具时可**手动导入**另一工具的单元做材料，规则只有一条：只能导入「加工史里还没有本工具」的单元（加工史 = 单元经过的工具集合，界面显示为左上/右上小标记，左 = 先进的工具）——同工具回流禁、两标满禁，套娃在结构上不可能。导入不消耗（被导入单元原地保留，可再导入重 roll、可自己注入）；导入产物 = 带累积徽章的新单元（如反应卡带 [事件,反应] 两标），原单元本体不动。单元不论徽章数（哪怕只有出生标）都可直接勾选**参与规划**；采纳规划后单元池不清空，清理由各工具面板的一键清理键手动执行。先后顺序由作者的导入动作天然产生，系统只记录不仲裁（徽章即顺序的显示）。**三个功能（随机事件 / 路人反应 / 规划）共用同一套提示词材料模板**：第 1 步确认勾选一遍，三处生成吃同一份材料（各自的生成任务指令不同，材料部分严格同源）。**注入模板序固定**：剧情 → 事件 → 反应，不给排顺序的旋钮。

### 2.6 一份规划的生命周期

材料收集（表/标签/世界书/玩法/最近对话/指导意见）→ 元素选择（事件、反应按需取用，可全跳）→ 生产草稿 → 审核（人工，或盲盒模式见 2.8）→ 注入生效（深度/角色/过期可配）→ 检查报告（继承向导口径）→ 按建议重写 或 完结归档。

- 历史归档上限 20 条，进行中那条永不丢；
- **跨聊天一切归零**：向导进度、注入、反应卡全是聊天作用域，没有任何东西需要跟到新聊天（作者会在一切稳定后才开新聊天）。

### 2.7 过期语义

- 事件与反应 = 「石子落进水里，要的只是扔下去那一刻的动静」——自动过期无所谓；
- **执行中的剧情注入不许自动消失**——手动管理可接受（「不介意通过增加工作量来提高扮演的稳定性」）。【意图：事件按层数过期从未实战跑过】

### 2.8 盲盒模式（信息差内容）【全部为意图】

适用四场景（作者枚举）：

1. **信息不对称**——牌局、道具选择、角色藏起来待兑现的计划或玩笑；
2. **真相隐藏层**——悬疑、密室逃脱（提前解密失去乐趣，不规划剧情又发散）；
3. **心理博弈张力**——预设节点、结局、情感走向的跌宕起伏；
4. **决策隐藏层**——信息不对等下真实做选择、增强沉浸，开放/多维结局。

解法（作者设计，推翻了助手的三个候选方案）：

- **生成时模型自判是否向作者公开剧情**（对「不公开导致剧情偏离的风险」做判断再决定揭不揭露）；
- 生成时提供「是否要查看剧情」的选项由作者预先选择，决定模型采用什么输出策略；
- 判断可选路径较窄时**预警**（多重兜底）；
- 剧情未执行且作者不知情时出了问题，不叫「事后偏离」——直接**重新设计整体结构 / 走开放结局风险回避**。

界面：**默认折叠 + 劝退提示，想看随时能看**；保密是自律级（本插件的提示词查看器翻得到注入内容，技术上无法对用户自己隐藏，作者确认「没必要做成军工级保密」）。

配套提示词：**强化扮演角色主导故事走向的能力**，把作者从「导演」挪到「观众 + 守护者」——防止被规划文本带偏成强制 OOC。

### 2.9 历史摘要 vs 记忆表格

共用入口，职责不重叠：

- **历史摘要** = 短期剧情的**详写** + 暂存（方便二次修改、防短时间内多次构思无留存）——服务两位数楼层内结束的短规划；
- **记忆表格** = 浓缩的**精华**、事实源——三位数、四位数楼层长线的进度就靠读表。

## 3. 数据生命周期总账

**每聊天数据五块**（chatdata 双层存储：热层 localStorage 毫秒写、完全不碰聊天文件；冷层 settings.json 低频冲写——切聊天/采用剧情/表格合并/关面板/5 分钟兜底；聊天身份 = 角色头像文件名｜聊天文件名，改名/分支会被认成新聊天，用设置页「数据备份与搬家」接回；异常退出最多丢 5 分钟窗口内的改动）：

| 数据块 | 内容 | 谁写 | 活多久 / 怎么清 |
|---|---|---|---|
| memory | 镜像 sheets、原表库快照、标签、已读、墓碑、召回配置、备份列表、清空事故标志 | 记忆表格页操作 + 三类事件的自动同步 | 跟聊天永存；备份超上限丢最旧；源表清空事故触发保护、绝不拿空数据覆盖 |
| story | 进行中剧情 + 历史归档（≤20 条，含检查报告） | 采用 / 完结 / 挂报告 / 删除 | 归档超上限丢最旧的非进行中条目；清历史保留进行中 |
| wizard | 向导进度快照（当前步 + 全部输入 + 生成结果） | 每次重渲染与输入改动 | 确认采用 / 取消向导即清空；分析在途刷新回「分析前确认」重发 |
| picks | 向导第 1 步的勾选口味（跨向导记住） | 第 1 步每次勾选变化 | 跟聊天永存 |
| books | 世界书页「启用」勾选（对话书单） | 世界书页勾选时 | 跟聊天永存 |

**全局设置**（settings.json 一整包，1 秒防抖）：API 连接与供应商方案库、搜索配置、检索五参数、指导预设（全局生效）、注入默认参数、事件库 + 维度层 + 掷骰三板块 + 最近掷出、世界书库 + 回收站、注入项、额外存储条目 + 玩法扫描窗口、玩法咨询草案、面板缩放、每聊天冷层 chatData。

**注入项生命周期**：scope=global/chat（chat 项绑定创建时的聊天 id）；按层数过期的每条角色回复 age+1、到期自动撤下（反应类注入同时未手改则逐层换段）；切聊天时撤销外聊注入、重放本聊的。

**旧数据**：曾存聊天文件 chatMetadata 的五块，读取时一次性迁走并从聊天文件删除（聊天文件瘦身）。

## 6. 未来愿望（只设计、不实现——跑完第一次完整战役前冻结）

### 6.1 自动监听

- **成本**：无容忍上限——交给便宜模型 / 主流模型轻量版本，每轮判断都行（10 轮内容约 1 万 token + 规划，花费不大）；
- **方案**：暂存「浓缩后的扮演要求总结提示词」（全量提示词的 1/5~1/10）+ 新生成文本对比判断；
- **输出**：偏离时冒红点（常驻指示器），点开看问题 + 给指导建议；被放任 → 上一轮模型刚输出完就执行判断与修正建议，下一轮作者输入时**隐身注入**；仍被无视 → **微调规划**；执行时才发现规划不合适 / 作者主动 OOC → 换一种提示通知；
- **锚点**：随规划重写作废；**锚点要能自己微调**（「固定锚点就没必要引入大模型了」）；判「事件是否已发生」= 对比最近 ~10 轮 + 记忆表最新 ~5 条；关键动作 = **进度条关键点**（达成自动推进、完成或对比表格确认后自动关闭、不再输出）；
- **无规划时也跑**：OOC + 文风重复检测（现有检查能力的轻量自动化，便宜模型跑），结果逐轮留存可回看——帮作者改善文风；
- **反向触发**（提醒「这段值得开个规划」）**暂缓**——判断标准未定（只看上下文？要不要世界书 + 记忆表？输入大则开支不划算）；
- **不要暂停开关**：知情时不会跑偏（跟着走或手动改），不知情时靠强化「角色主导故事方向」（即 2.8 盲盒配套）。

### 6.2 长线章节规划

- 结构 = **粗细混合 + 保底楼层**：问作者「最低想让剧情走多少楼」，随时调整、提前结束、追加走向要求；
- **已完成部分不喂摘要——读记忆表格认实际进度**；规划对象只保留大纲 / 走向；
- 种子（新角色 / 伏笔）规划阶段显式列出；「是否要新角色」做成选项。

### 6.3 共享地基

两个愿望是同一块地基：**把剧情状态从上下文窗口搬进结构化对象持续维护**——上下文窗口是易失内存（十几万层一满就「忘」），剧情状态是磁盘（锚点 + 进度 + 大纲长期存活）。

## 7. 验证台账

**【实战】**（真实聊天里验证过）：

- 作者的编辑习惯本身（日常修正只在表尾两三行、大修节奏约三千层、久远内容一次维护即稳定）——长期使用源插件的真实习惯，先于本插件存在。

**【意图】**（设计意图，待第一次完整战役 / 首次大修验证后搬栏）：

- 镜像删除的降噪实效（删时空表 / 物品表后规划质量是否可感提升）；
- 名字标签 + 事件类型标签的群像卡筛法实际覆盖度；
- 指纹在大修下的表现 + 大修后处置流程（人工核验 + 重打标）；
- 事件注入按层数过期的手感（过期了剧情没演到怎么办）；
- 检查报告继承向导口径后的查重效果；
- 对称读取规则下事件 / 反应的实际互相影响；
- 盲盒模式全套（四场景 + 模型自判公开 + 折叠劝退）；
- 自动监听与长线规划（§6，连设计细节都还要再打磨）。
