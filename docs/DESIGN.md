## 1. 这个产品是什么

一句话：坐在角色扮演聊天之上的**剧情守护层**——替扮演模型记住该记的、看见该看的，替作者管住剧情的方向与质量。

作者原话（产品的全部出发点）：

> 「我在酒馆玩角色扮演……都是在模型的设定和智力内让它更好的扮演角色，更接近真实，更像人，创造出更精彩的剧情。」

三个具体目的（作者原话）：**管理文件、提纯提示词、让扮演更加贴合。**

为什么需要它（作者的全知视角论，三个工具共同的存在理由）：

> 「过去的时间就是过去了，我参与的事情没必要再讨论，我没推动的事情不存在，角色不会自己发生我不知道的事情——换句话说，我是全知的。哪怕约会一千次，约会的流程也只取决于模型固定的创造力，而不会有新的变化。」

RP 的世界里没有「镜头外发生的事」，一切新鲜感必须被显式制造——这是随机事件、路人反应、剧情规划三个工具的立身之本。

## 2. 核心概念

### 2.1 一行记忆 = 对角色行为有影响的事件

不是「一条记录」。判断一行记忆价值的标准只有一个：**它会不会改变角色接下来的行为**。镜像、打标、召回的一切设计都为这个标准服务。

### 2.2 双读者模型：原表与镜像

插件里有两位读者，各看各的数据，**分叉是有意的**：

- **扮演模型**（主对话）看**原表**——记忆增强表格插件的数据；
- **规划/检查模型**（本插件的规划向导、检查报告）看**镜像**——本插件按聊天维护的副本。

镜像的定位是**规划侧的策展层**：删掉对规划无意义的表（时空记录表、物品表等每轮更新的噪音），让规划模型注意力集中、降本增效。作者原话：「我给扮演模型看的内容和我给规划模型看的内容可以不一样。」

- 日常操作以**删**为主；
- **改单元格**基本不用但保留——它是双读者差异的具象化（有些扮演要注意的细节，规划不需要落实）；
- 边界要说破：镜像里删一行，扮演模型照样「记得」这件事；**修扮演侧的事实只能去源插件改**。本插件对原表唯一的写路径是备份恢复（只增不改）。

### 2.3 行的身份 = 内容指纹

镜像行的身份 rid = hash(表uid + 列名 + 内容)。这是自然键身份：**内容一变，身份即换**——被改写的行会以「新行」姿态重新进来，旧标签、已读标记、删除墓碑都认不出它。

- 日常修正只发生在表尾两三行（最新进展），指纹漂移影响的只是本来就在变动的行。【实战：这是作者长期使用源插件的真实习惯，先于本插件存在】
- **大修**（每约三千层一次）：合并改写压缩 + 删旧行，覆盖近三千层新增内容。指纹雪崩（标签作废、墓碑失效、满屏新行）在这个场景**真实会发生**。作者接受代价并把处置纳入大修流程本身：**大修后人工核验一遍 + AI 重新打标**。这是标准流程，不是技术债。【意图：大修流程从未实跑过】

### 2.4 口径：这次给模型带哪些记忆

默认答案（作者原话）：「**越是贴合角色的越要，越是无关的越舍。**」相关性三要素：出场角色、剧情合理不重复、前进方向。

- 单主角卡：全量输入（完整关系成长经历贴合扮演）；
- 群像卡（如十人卡）：**名字标签 + 事件类型标签**组合筛（为此移除过单行 3 标签上限）。

口径是**两层模型**，各管各的：

| 层 | 位置 | 管什么 |
|---|---|---|
| 全局默认层 | 记忆表格页（每表一份） | **召回列**——剔除「角色名/备注」类对模型无用的列（列要留着给源插件显示，只在召回时剔除） |
| 单次覆盖层 | 向导第 1 步 | 表勾选 + 三档位（停用/按标签/常驻全量）+ 标签 + 表尾最新 N 行 |

- 「参与召回」总开关已退役（向导勾选足够）；
- **检查报告口径（已落地）**：第 3 步人工二检**继承向导第 1 步**的表/标签选择（读本对话存的第 1 步勾选，与「按建议重写」同一份）——单人卡全量无感；群像卡只查同类事件重复、无关事件不计入；兜底 = 写指导意见打回。

### 2.5 三工具模型：规划 / 随机事件 / 路人反应

三者不是流水线，是**工具箱**：

- **随机事件**与**路人反应** = 对等的并行工具（作者原话「不是附庸品」），随时单独取用；
- **规划** = 「有多次重试机会的个性定制思维链」——**只规划不扮演**，让规划模型与扮演模型各自能力最大化。

**单元制**（互相干涉的正解；2026-08-25 定稿并落地，取代早期「自动对称读取」草案——作者要控制权，不要自动；2026-08-26 三处修订见下）：两个现场工具的产物 = **单元**（暂存态，每工具名下 ≤3，满了禁止再生成、先手动删）。生成任一工具时可**手动导入**另一工具的单元做材料，规则只有一条：只能导入「加工史里还没有本工具」的单元（加工史 = 单元经过的工具集合，界面显示为左上/右上小标记，左 = 先进的工具）——同工具回流禁、两标满禁，套娃在结构上不可能。导入不消耗（被导入单元原地保留，可再导入重 roll、可自己注入）；导入产物 = 带累积徽章的新单元（如反应卡带 [事件,反应] 两标），原单元本体不动。**导入＝既定方向（2026-08-26 定则，起因：用户报事件单元导进路人反应不起关联——接线本对称，弱在任务指令没把导入当锚点）**：导入的单元按「将要且一定会发生的方向」对待，生成结果必须与它咬合，是硬要求不是可有可无的参考——事件侧顺着导入的反应口径发展（不复写同一件事、不与它矛盾），反应侧围绕导入的事件出卡（显著性、即时口径、余波都按它定；没导入才从最近对话里找）。**导入最多勾一项 + 产物正文自带前因（2026-08-26 E11 定则，起因：用户报多勾无意义、双徽章单元正文只剩最后一道工具的内容——原始单元一删前因就断，注入后模型也不知道「这件事」指什么）**：导入选材最多勾一项（勾了新的自动替掉旧的）；导入产物的正文把源单元内容原样嵌在开头作「前因」小节（存 payload.origin，随分析发送、转隐身注入、正文重算与注入到期逐层重算都带着）——原始单元删了链条也在，模型看到的是「前因＋本工具内容」的完整链条。**单元 = 带标签的纯文本提示词块（2026-08-26 定则，后续一切修改的准则）**：像生产材料一样作为纯粹提示词使用（定则管的是**材料语义**——发给模型的就是拼好的整块文本；卡面显示保留各工具生成结果的原有形态，反应卡的分栏字段展示不在替换范围，同日返工澄清）——工具面板只管生成，入池单元统一在向导第 1 步「插入单元」区查看与操作（勾选随分析发送 / 点单元名看正文 / 转隐身注入 / 删除 / 各组清空键）。**参不参与规划是规划侧的事（2026-08-26 修订）**：入池单元在第 1 步「插入单元」勾选区决定是否随分析发送——工具面板的卡片上没有这个开关（已注入的反应单元灰显不可勾：生效注入会让规划与检查自动附带同一口径，再勾就是同文进两次）；采纳规划后单元池不清空，清理由「插入单元」区各组的清空键手动执行。**生成先出草稿、立卡即定稿（2026-08-26 两轮修订合流）**：两工具的生成（事件：掷骰 / 大模型随机 / 按意见生成；反应：生成反应卡）都先出草稿卡，点「立为单元」才入池（再生成换掉草稿，草稿随聊天存不丢）；事件的走向选项**三选一或不选**，立卡时裁剪——没选 = 选项全砍（只作参考材料）、选了 = 只留那一个，入池后不可改选走向（想换 = 重新生成）。意见路径走大模型：「按意见生成」遵循意见即兴（意见是方向不是剧本）；意见与随机**严格二选一**——意见框有字时掷骰 / 大模型随机 / 导入勾选全部灰置。「大模型随机」无条件把事件库已有条目作为**防复刻清单**随行（2026-08-26「参考事件库」勾选退役）；反应卡由模型顺带给浓缩短标题作单元名（与事件同款）。先后顺序由作者的导入动作天然产生，系统只记录不仲裁（徽章即顺序的显示）。**三个功能（随机事件 / 路人反应 / 规划）共用同一套提示词材料模板**：第 1 步确认勾选一遍，三处生成吃同一份材料（各自的生成任务指令不同，材料部分严格同源）。**注入模板序固定**：剧情 → 事件 → 反应，不给排顺序的旋钮。

### 2.6 一份规划的生命周期

材料收集（表/标签/世界书/玩法/最近对话/指导意见）→ 单元取用（随机事件/路人反应两工具面板里生成与互导——面板只管生成；入池单元在第 1 步「插入单元」区勾选、查看与注入；可全不用）→ 生产草稿 → 审核（人工，或盲盒模式见 2.8）→ 注入生效（深度/角色/过期可配）→ 检查报告（继承向导口径）→ 按建议重写 或 完结归档。

- 历史归档上限 20 条，进行中那条永不丢；
- **跨聊天一切归零**：向导进度、注入、反应卡全是聊天作用域，没有任何东西需要跟到新聊天（作者会在一切稳定后才开新聊天）。

### 2.7 过期语义

- 事件与反应 = 「石子落进水里，要的只是扔下去那一刻的动静」——自动过期无所谓；
- **执行中的剧情注入不许自动消失**——手动管理可接受（「不介意通过增加工作量来提高扮演的稳定性」）。【意图：事件按层数过期从未实战跑过】

### 2.8 盲盒模式（信息差内容）【全部为意图】

适用四场景（作者枚举）：

1. **信息不对称**——牌局、道具选择、角色藏起来待兑现的计划或玩笑；
2. **真相隐藏层**——悬疑、密室逃脱（提前解密失去乐趣，不规划剧情又发散）；
3. **心理博弈张力**——预设节点、结局、情感走向的跌宕起伏；
4. **决策隐藏层**——信息不对等下真实做选择、增强沉浸，开放/多维结局。

解法（作者设计，推翻了助手的三个候选方案）：

- **生成时模型自判是否向作者公开剧情**（对「不公开导致剧情偏离的风险」做判断再决定揭不揭露）；
- 生成时提供「是否要查看剧情」的选项由作者预先选择，决定模型采用什么输出策略；
- 判断可选路径较窄时**预警**（多重兜底）；
- 剧情未执行且作者不知情时出了问题，不叫「事后偏离」——直接**重新设计整体结构 / 走开放结局风险回避**。

界面：**默认折叠 + 劝退提示，想看随时能看**；保密是自律级（本插件的提示词查看器翻得到注入内容，技术上无法对用户自己隐藏，作者确认「没必要做成军工级保密」）。

配套提示词：**强化扮演角色主导故事走向的能力**，把作者从「导演」挪到「观众 + 守护者」——防止被规划文本带偏成强制 OOC。

### 2.9 历史摘要 vs 记忆表格

共用入口，职责不重叠：

- **历史摘要** = 短期剧情的**详写** + 暂存（方便二次修改、防短时间内多次构思无留存）——服务两位数楼层内结束的短规划；
- **记忆表格** = 浓缩的**精华**、事实源——三位数、四位数楼层长线的进度就靠读表。

## 3. 数据生命周期总账

**每聊天数据六块**（chatdata 双层存储：热层 localStorage 毫秒写、完全不碰聊天文件；冷层 settings.json 低频冲写——切聊天/采用剧情/表格合并/关面板/5 分钟兜底；聊天身份 = 角色头像文件名｜聊天文件名，改名/分支会被认成新聊天，用设置页「数据备份与搬家」接回；异常退出最多丢 5 分钟窗口内的改动）：

| 数据块 | 内容 | 谁写 | 活多久 / 怎么清 |
|---|---|---|---|
| memory | 镜像 sheets、原表库快照、标签、已读、墓碑、召回配置、备份列表、清空事故标志 | 记忆表格页操作 + 三类事件的自动同步 | 跟聊天永存；备份超上限丢最旧；源表清空事故触发保护、绝不拿空数据覆盖 |
| story | 进行中剧情 + 历史归档（≤20 条，含检查报告） | 采用 / 完结 / 挂报告 / 删除 | 归档超上限丢最旧的非进行中条目；清历史保留进行中 |
| wizard | 向导进度快照（当前步 + 全部输入 + 生成结果） | 每次重渲染与输入改动 | 确认采用 / 取消向导即清空；分析在途刷新回「分析前确认」重发 |
| picks | 向导第 1 步的勾选口味（跨向导记住） | 第 1 步每次勾选变化 | 跟聊天永存 |
| books | 世界书页「启用」勾选（对话书单） | 世界书页勾选时 | 跟聊天永存 |
| units | 两工具暂存单元池（每工具 ≤3）+ 两工具生成草稿 + 面板意见草稿 | 工具面板只管生成（先草稿）/导入；第 1 步「插入单元」区查看/勾选/注入/清空 | 跟聊天永存；采纳规划**不清池**，清空走「插入单元」区各组清空键（只清本工具名下） |

**全局设置**（settings.json 一整包，1 秒防抖）：API 连接与供应商方案库、搜索配置、检索五参数、指导预设（全局生效）、注入默认参数、事件库 + 维度层 + 掷骰三板块 + 最近掷出、世界书库 + 回收站、注入项、额外存储条目 + 玩法扫描窗口、玩法咨询草案、面板缩放、每聊天冷层 chatData。

**注入项生命周期**：scope=global/chat（chat 项绑定创建时的聊天 id）；按层数过期的注入创建时记下**楼层基线**（楼数 = 已落地的角色回复数，user 楼不计——一层 = 一条角色回复），已过层数 = 当前楼数 − 基线：滑动/重新生成只是替换最后一条回复、楼数不变不吃层，删楼层楼数只减、推导不为负（2026-08-26 B1 拍板，取代旧的「每次生成 age+1」，老注入按已有进度折算基线不跳变）；到期自动撤下（反应类注入同时未手改则逐层换段）；切聊天时撤销外聊注入、重放本聊的。

**旧数据**：曾存聊天文件 chatMetadata 的五块，读取时一次性迁走并从聊天文件删除（聊天文件瘦身）。

## 6. 2.0 长线规划（设计定稿 2026-08-28；监听已落码，其余整节【意图】）

> 状态：监听（6.1）已落码（js/listener.js，2026-08-28）；知识库（6.9）已落码（2026-08-29，真机十七轮修订）；**长线生成管线（6.2 六步）已落码（2026-08-30 第十八轮，js/longform.js＋「长线规划」页签，落码注记见 6.2 末）**。其余 2.0 部分——混合重编、暂停恢复、归档、场景元素卡、动作指导卡——仍零代码，写码须用户明确指示的节奏口径不变。
> 2.0 是什么：1.0 管短期规划（单场景、几层楼内的剧情指导）；2.0 补长线——以「一本书」为尺度的剧情规划，横跨几十到几百层楼，产出指导文本与节点表。但这些产物**不直接注入扮演模型**，全部交给「监听」逐回合执行（6.1）。
> 共享地基：监听与长线管线是同一块地基——**把剧情状态从上下文窗口搬进结构化对象持续维护**。上下文窗口是易失内存（十几万层一满就「忘」），剧情状态是磁盘（推进锚、进度、大纲长期存活）。

### 6.1 监听 = 执行引擎（2.0 头号架构决策）

早期设想把监听排在最后做、可无限期推迟——**已作废**：指导文本与节点表一旦直接注入扮演模型，它看到全图会第一轮就剧透、一口气把后面的剧情赶完。正解是全部指导喂给监听，逐回合判定、逐回合放行微量指导；指导不注入就没法执行，监听是整条执行链的地基，故最先开发。原「先做手动模式保底」的提案随之作废。

**分界线（2026-08-28 用户定案）**：场景元素类内容（状态句，无推进判定需求）直接隐身注入两轮、不经过监听；剧情指导类内容（章文本、节点表、动作指导序列）全部经过监听。

**逐回合循环**：扮演模型每轮输出后立即判定（赶在用户下一次输入前备好指导）→ 拿剧情上下文与当前节点的总结性文本比对 → 判定进度（达成＝「点亮」该节点，进度随之推进）→ 生成下一回合的微量指导 → 隐身注入扮演模型（隐身注入＝不显示为聊天消息、直接进入扮演模型输入的注入方式）。

- **输入（全量、不封顶）**：当前聊天全部未隐藏楼层 ＋ 当前最小剧情单位全文 ＋ 出场角色的世界书条目（不限条数）＋ 两个小附件——下一节点的标题一句（收尾方向用，知名不知戏）＋ 本章已点亮节点的标题串（防重复演绎的索引；全量楼层读入后只剩这一职责）。防剧透边界：以最小剧情单位为界，章文本与节点表的全图不进任何输入。可再附加世界书与记忆表格——监听材料与 1.0 材料面板**共用一套获取逻辑**（用户口径：现在不剥离、不定死，将来要分时做减法即可）。**单位槽来源不限（2026-08-28 新增）**：2.0 管线产物、手动导入、1.0 剧情规划产物直接挂载——1.0 规划视为同等的最小剧情单位、同样分节点（节点化方式与退位语义见 6.8 挂账）。
- **输出（微量指导）**：结构＝目标句＋动作提示；**不设字数上限**——要限制的是监听读取的剧情单位（输入侧），不是输出；一轮多角色且各有负责内容时两三句指导不完是常态，宁详勿简。每轮与已推进内容、进度比对后**重新生成**，措辞随进度变化、不复读。
- **注入通道**：独立注入槽，比 1.0 现有注入更靠近上下文末端；系统便签风格；滚动覆盖（新一轮盖掉上一轮）。与短期剧情规划的注入一般不同时存在，共不共用通道不重要。同轮并存时场景元素卡在前、监听指导在后。
- **频控**：2~3 轮内只要有有效对话（剧情在推进）就不降级——指导内容天然随进度变化，无复读问题；复读只在推进停滞时才成为风险。频控行为统一归**介入强度旋钮**调节（见下），不设固定档位规则。**节点衔接＝用户手动**：最小单位刚执行完、要不要接续下一个单位由用户决定（防剧情过紧、失去自由扮演空间；2026-08-28 拍板：只做手动，不留「自动接续」档）。慢热缓冲保留：刻意慢节奏的回合没有任何节点推进才是正确结果，不算卡死。
- **行为规范**：判节点达成必须引用具体楼层内容作证（防「假完成」）；某轮决定不发指导必须留痕说明原因（防无声跳过；留痕面板滚动留存默认 50 轮、设置可调）；判定增设第三态「卡死」——出现时不自动微调规划，升级用户人工拍板。
- **指示器与旋钮**：偏离提醒＝红点（常驻指示器，点开看问题与指导建议），亮在酒馆「魔法棒」菜单的剧情规划器条目处——写码前先在真实界面核对魔法棒面板的注册与角标机制，勿凭想象写选择器。设置项＝两轴旋钮：**达成判定松紧**（多严算偏离）＋**介入强度**（指导发多勤多强，接管全部频控行为）。
- **监听模型**：设置页**固定项**（2.0 其余生成都是每次自选模型，唯监听例外），默认＝设置里第一个副API（规划模型）供应商方案。成本立场：逐轮判定交给便宜模型或主流模型轻量版本，用户对监听成本无容忍上限；注意全量楼层输入下单轮 token 随聊天长度增长，实际开销以实测为准。工作难度定位（用户校准、勿夸大）：多数回合只是轻量比对，真正难点三处——分级判定（偏多少算达成；「圆不回来」是对未来剧情的反事实推测）、微量指导的现场生成（推剧情、不剧透、不抢跑三线走钢丝）、边缘回合（戏中戏的「假装完成」、用户发的脱离角色元对话、刻意慢节奏——没有推进才是对的，不得误报卡死）。
- **三级降级路径**：单次失败→坏输出回传重发一次，仍败→本轮静默跳过并留痕（**绝不复用过期指导**）；连续 3 次失败→「监听失联」提醒＋暂停监听；API 彻底不通→挂起等用户处理。任何降级都不得滑向「把全图直接注入扮演模型」的盲指挥；进度账（6.4 两本账）不因监听故障变动。
- **无长线规划时也跑**：轻量的脱离角色检测＋文风重复检测（便宜模型），结果逐轮留存可回看（帮作者改善文风）；「这段值得开个规划」的反向提醒**暂缓**（判断标准未定）。正常运行不设「暂停监听」开关——知情时跟着走或手动改即可，异常停机只走三级降级。执行中发现规划本身不合适、或作者主动跳出角色→换一种提示方式（与偏离红点区分）。

### 6.2 长线生成管线（六步）

1. **骨架**：输入楼层总数与材料（1.0 材料面板自选＋世界书条目自选＋「本次长线想法」输入框＋保底楼数），产出全书压缩大纲，只到「卷」级措辞；各卷楼数总和由插件校验，不让模型自行提议密度分布。
2. **切块**：切成部分/卷，只分配楼层预算、不产执行节点（文本未生成，完成标准没有对照物）；子块至少 2、不设上限。
3. **分块具体化**：逐块生成卷级详细文本，内嵌「推进锚」（预先埋设的剧情检查点；每卷至少 4、不设上限——现阶段固定下限，后期改为生成前可选或模型自判，见 6.8）；锚与锚之间标注「本锚间自由演绎」；展开程度匹配楼层预算。
4. **拼接**：各卷文本拼成完整大纲。
5. **审阅改**：整体审阅、修改。
6. **再切小**：卷切成章（一章至少 20 层楼、不设上限，2026-08-28 定；原 10-20 区间作废）、章内切出节点（带可对照的完成标准，每章至少 3 个），一步到位；推进锚是切章的刀口。

之后的执行交给监听（6.1）。种子（新角色/伏笔）在规划阶段显式列出，「是否要新角色」做成选项；已完成部分不喂摘要——实际进度认进度账（6.4），规划对象只保留大纲与走向。

### 6.3 楼层与预算

- **换算锚**：一层楼＝一条角色回复（口径同 §3 注入项）；一轮总输出约 1000 字、其中约 200-600 字回应用户输入，真正推剧情的「有效推进」在一个区间内估量（用户输入推动越少越近下限；两端做设置项，400/800 是用户举例的示意默认值而非实测事实——用法＝当成区间综合衡量，不做固定数值换算，2026-08-28 澄清）。所有涉楼提示词带换算锚「一层楼≈有效推进字数区间」（区间两端读设置）——「楼层」是酒馆玩家行话，API 模型不懂。
- **预算管线**：楼层数是最先输入的参数，切块时分配一次、再切小时再分配一次；用户不填用默认值兜底。楼层只是生成参数，不做「进度太慢」类节奏警报。
- **预算可手改（第二十轮）**：切块的分配结果不是死的——卷楼数在长线页就地编辑（卷卡「编辑骨架」），楼层总数随之＝各卷之和；改完切过章的卷要重跑「再切小」重配章预算。
- **预设不传导、允许溢出**：各预算单元的楼层一经分配即固定，写超不向后传导（例：10 层分 3+3+4，第一个单元实写 5 层，超出的 2 层只算它自己的事，其余单元与总数不变）。
- **书-卷-章-节点四层**：全书分卷、卷分章、章内排节点；每一层都有继续细切的权利。

### 6.4 关键机制

- **节点**：最小剧情单元，文本块带可逐条对照的完成标准；达成口径＝「角色动作偏向某目标即算达成」（直接写进提示词）。
- **两本账**：**产出文本账**（未执行的规划内容，混合时随便重写）＋**进度数据账**（哪些节点已完成——正常路径是监听判定点亮，用户的显式操作也可改；混合重写与再生成不得动它）。
- **伏笔＝注定任务**：不做独立台账。骨架阶段点名后挂到具体节点成硬规则，完成判定并入该节点的完成标准；执行失败＝报错交用户处置（回滚重埋或整条删除）。
- **打碎重混（操作名「混合」）**：用户显式发起——把新导入的指导材料与当前剩余规划交给规划模型打碎重编成一份新规划，两根进度条合为一根；已完成节点冻结进历史，新规划只覆盖剩余剧情、只重写当前最小单元。混合时给模型看的既有剧情＝「校准窗口」，按 1.0 材料管线口径取数，窗口大小数值可调、设 0＝全部未隐藏内容可见。**服装/场景类不参与混合**（分界＝是否需要节点推进，不是材料体量）。任何指导材料都可导入打碎重编（动作指导卡、1.0 规划产物、路人反应单元、随机事件单元共用一套组装模板）；每次混合都带「本次想法」指导框，其内容＝最高优先级。
- **暂停恢复**（短期剧情规划与长线的交互）：用户往当前剧情注入短期剧情规划时，长线进度自动暂停（界面提示「注入当前剧情会暂停长线进度」）。指导结束后两档处置——**A** 按卷级单位（书-卷-章-节点第二层）对照判断影响、输出**影响系数**：影响不大→从上次进度继续；影响大→提醒用户、由用户重新规划剧情。**B** 直接把当前最小长线单位与刚做的剧情规划打碎混合（同「混合」操作）。影响评估的对照问题清单与评估提示词待起草送审（评估调用哪个模型随之一并定）。
- **归档＝注入前过滤**：防重复不在注入层下「别重复某某」的指令——直接下禁令反而诱发重复（白象效应）——而是在注入前把用过的内容过滤掉。构成：**整套记录**（整套服装/造型用过就整套装档）＋**单品禁令**（标志性单品永不再用）＋**场景桶**（场景分桶存放；重复同场景外出必须备注「特地选了和上次一样的」，新颖互动绝不复用）。各角色各自建档、互不封锁；条目涉及哪些角色由模型生成时自标。2026-08-29 定：归档与知识库用后账**共用一套记账设计**（见 6.9）；服装跨清单组合（一套服装的多个元素来自多张清单）用过的**组合整体入账**、可固化为**固定搭配**有意复用——组合机制细节随服装库落地时设计。
- **场景元素卡**：描述当前场景/服装状态的「状态句」，直接隐身注入两轮后自动过期（两轮保证加载：卡是种子，上下文里长出来的描写才是活状态）。历史卡滚动留存默认 5 份（设置可调，2026-08-28 定；原 3-5 区间作废），超出清最旧；留存档与归档数据分库。换场景才生成新卡；没有卡时 1.0 记忆表格的服装列兜底。不参与混合、不经过监听。
- **动作指导卡**：只指导标志性动作——每个角色一组有序的「目标动作序列」（目标有序，序列即节点序列）；至多 10 个角色同场、输出写长写细；一轮连贯动作偏向任一目标即算该目标达成；建议楼数由模型给范围而非定值。经过监听执行。
- **两套规划并存**：1.0 短期规划与 2.0 长线规划并存，混合重编不默认偏向哪套。

### 6.10 世界书条目自选（2026-08-29 第七轮定稿并落码；2.0 骨架「世界书条目自选」的提前落地）

**动机**：性知识这类「照着写」的材料要的是**原文整条随行**，不是「选着用」——三档位（停用/关键词/常驻）完全不适配：关键词碰运气（场景里没出现关键词就带不出）、常驻进插件**全部**模型调用且不能按次控制（规划要用、打标不要用，没法表达）。用户在规划开始前也没法按次自选世界书。

**机制**（挂在剧情指导页第 1 步，与知识库抓取同款悬浮面板）：

- 第 1 步工具行新增「世界书自选」入口＋悬浮面板：**按书分组**列出条目（书名做分组头），勾哪条哪条**整条原文**随分析进材料；不看关键词/常驻/对话启用书单——勾选就是唯一的口径，禁用的书与条目照样能勾（自选＝点名，与检索状态无关）。
- **与检索命中去重，自选优先**：同一条目既被关键词检索带出又被自选勾中时，只出现在「自选世界书条目」小节，检索小节里不再重复出现。
- 勾选**随对话记忆保存**（chatdata 的 picks 块，与清单勾选同层），刷新/回第 1 步不丢；条目或书被删后勾选静默失效（发的时候找不到就不带）。
- **无冷却**——「照着写」的材料每次都该在场，冷却没有意义；知识库（选着用）才配冷却。
- 只进规划向导的分析调用（随机事件/路人反应/检查报告不自动带——它们的材料口径各自独立，不跟着向导走）。
- **面板交互（2026-08-30 第八轮加）**：按书折叠——默认全部收起，勾选时点「展开」才摊条目；搜检索词时命中的书自动展开（显式点过「收起」的仍尊重）。条目行**只显示名字**（条目标题；无标题显示「条目 N」），原文整条在行的悬浮提示里看——行面保持紧凑，发送的仍是整条原文。

### 6.11 规划生成的行为约束（2026-08-29 第七轮定稿并落码；提示词层＋两处本地机制）

真机反馈暴露的四类规划行为问题与对策，全部作用在 1.0 规划向导的分析调用上：

- **时间顺序三句**（提示词层）：①材料各小节与条目的排列顺序**不代表时间先后**（两张清单按序拼接被模型当时间线读是第七轮实测病灶）；②对话或用户构思里给出当前时间的，**按它排程**（上午 11 点就该排午饭前后，不排晚饭）；③条目带时段类字段（表头含「时段」或字段值含时间词）的按它排——表头可加「时段」列表达，无新机制。
- **防复刻骨架清单**（本地机制＋随行小节）：所有旧防重复条款都是往后看材料的（对话/记忆/历史摘要），**放弃的草稿哪边都不在**——这是连 roll 收敛的根因。现「放弃保存→再分析」视为重 roll，随行「近期草稿骨架」小节：每版一句话概括＋各节点阶段名，**最近 5 份为限，确认采用（或转隐身注入）后清空**；新规划的骨架不得与清单里任何一份高度雷同。跳转回第 1 步直接再分析（旧草稿还在）同样先入骨架账。「重新生成」保持按修改意见修订的语义，**修改意见为空时按换一版处理**（上一版随行但标注「换一版：不要沿用其骨架与安排」）。
- **构思框升硬要求＋节点下限**（提示词层＋设置项）：用户构思里的数量类要求（「多写些节点」）一律按**下限**落实，不许打折；用户没点名时，节点数下限进设置项「规划节点下限」（默认 5、不设上限——节点是将来监听挂载的判断点，示例数量会被模型当上限用，所以只写下限）。beats 数组说明里写明下限。
- **user 不可编排（四层）**：第一层系统提示词**三禁一豁免**——禁替 user 做动作、禁替 user 说台词（含「user 答应后」这类把 user 的回应写成既成事实的写法）、禁预设 user 的心理反应；豁免＝对话或构思里 user 已明说的意愿可当前提。第二层**条件式接口**是唯一合法写法——涉及 user 的部分一律写成「若 user X 则 Y」（可多接口可分支），且**每个节点的核心推进不依赖 user**（user 接口是挂件不是地基，删掉挂件节点仍成立）。第三层 beats.content 字段说明内嵌短版（贴生成点，项目先例＝risks/knowledgeUsed 都靠 schema 格子执行住）。第四层坏好对照示例各一组，配防复读护栏（学结构不学内容）。同类条款扫全：随机事件、路人反应提示词同款加「不替 user 写行为与台词」。**本地黄牌**（人工二检页）：本地正则扫规划文本里「user＋说/答应/承诺/主动/帮她」类句式，逐句亮牌提醒——只提醒不拦截，不阻止采用。

**第十轮修订（2026-08-30 凌晨真机反馈，同节追加）**——三件：

- **点名要求全面升硬要求**：构思与修改意见里点名的要求从「数量类」扩到**全部类别**——数量、价位或金额（候选条目带价格区间的以条目为准）、时间日期、由谁发起或由谁挑选（点名了发起权归谁就不得转手，尤其不得转给 user）、地点、身份资格。起因＝全量礼物清单（条目带「价格区间」列、随材料全文进模型）＋修改意见点名「礼物不低于七位数、由陆星棠挑选、注意浴室是今天」，产出仍是 user 提前安排、价位不明——第七轮只把数量类写成了硬约束，其余点名要求无任何条款兜着，模型按默认分布走。原「节点数量是硬要求」条款并入此条，节点下限（minBeats）条款保留原样。
- **事实一致性条款（新增）**：对话记录、记忆表格、历史摘要里已发生的事是既定事实——发生在哪天就是哪天（今天上午发生的事不得改写成第二天），后续排程只能从既定事实之后往后推；角色与 user 的既定设定（年龄、身份、能力、资格——从对话、人设卡、记忆表格读到的）是硬约束，规划不得安排设定不允许的事（如未成年开车）。起因＝记忆表格与上下文都有「今天上午」、规划仍把约会写成第二天，且出过未成年 user 开车的剧情——与时间顺序条款互补：时间顺序管「现在几点、往后怎么排」，事实一致性管「已经发生的事不许挪日子、设定不许破」。
- **黄牌展示改一行总述**：扫描逻辑不动（句式表原样），人工二检页只报「发现 N 处疑似替 user 编排的句子」＋一句合法写法提示，撤掉逐句清单（用户拍板「展示一个总体的输出就够了」）。

**第十一轮修订（2026-08-30 凌晨真机反馈，同节追加）**——两件：

- **思考标头自动重试（api 层，全部调用受益）**：deepseek 等推理模型经部分中转会把思考段直接写进正文、开头打「## 思考（Thinking）」类标头。chatCompletion 加外层包装：输出以思考标头开场＝思考混进了正文（本插件所有任务都要求 JSON 开场）——流式在标头刚露头时掐断（省 token）、非流式收完判定，命中即以原请求自动重试一次；重试的一发不再掐断（再掐可能把思考段后的完整内容丢在半路），仍带标头按原样返回＋toast 提示换模型或勾「关闭思考」。判定只认「#/思考或 Thinking/行尾」的独立标头行（looksLikeThinkingHeader 纯函数，「思考突破」这类普通标题不误伤）；重试请求服务商照常计费、onUsage 累进上层对账（planner 累加制），流式掐断那发收不到 usage——与手动中断同口径。
- **黄牌展示再修（纠正第十轮过头形态）**：用户澄清上轮「总体输出」指不要每处各开一张粗体标题卡（第九轮形态），不是只剩总数不说哪里——现合成一张卡：总数一行＋触发句子逐句列在同一张卡里（扫描逻辑两轮均未动）。

**第十二轮修订（2026-08-30 真机反馈「时间错位一直在」，同节追加）**——两件落地＋一件提案自驳：

- **时间锚外化（currentTime 字段）**：时间错位的机理＝相对时间（今天/明天/第二天）没有固定寄存的「现在」，模型写规划时被体裁惯性拽着把近事归档成「昨天」，且一处写错后续参照系整体漂移。现 plan 对象第一字段 `currentTime`：模型排程前先把「现在是什么时候」从对话/构思/记忆表格里读出来写在这里（材料无线索如实写「未指明」）——锚点外化到生成点上，后续相对时间全以它为参照。结果页新增「时间基准」行原样展示：模型把「现在」读错（读成明天）一眼可辨，用户改规划文本即可。规划文本（formatPlan）首行带「时间基准：X」（「未指明」不写）——随注入/采用一并带给扮演模型，主对话侧同样有锚。
- **两遍调用·第二遍对齐修改（用户拍板「第一次生成，第二次对齐要求修改」）**：第一遍照常生成；解析成功且设置开着时自动追加第二遍——同一份材料（含联网纪要，联网不重判、不重复计搜索费）＋第一遍 plan 草稿再发一次，系统提示词换成「对齐审校员」：只拿四类要求逐条对账（①时间基准重读＋相对时间对锚 ②既定事实与设定 ③点名硬要求 ④user 不可编排），**只改违反处、其余原样保留（校对不是重写，选材与 knowledgeUsed 不动）**，输出 `{plan, fixes[]}`；checks 不重查不重发（它是对对话的判断，不随 plan 修订而变）。合并规则：plan 取第二遍、checks 沿用第一遍，`fixes`（逐条改动清单）与 `alignState` 挂在结果上，结果页新增「第二遍对齐修改」行逐条展示。第二遍失败或被中断**不报废第一遍**：结果照常交付、alignState 如实标注（中断那半已生成的部分照常计费）。计费约 ×2（输入两遍全量材料＋两份输出；**本段计费与「系统提示词换成对齐审校员」的拼装方式已被下条第十三轮修订取代**——第二遍已尾巴化、计费约 ×1.2～1.4），运行页阶段标注「第二遍 · 对齐修改中」，两遍 token 实报合并上账单行；思考原文两遍拼接（【第二遍思考】分节）。设置页「生成后对齐修改（第二遍）」可关（默认开）。范围＝规划向导（含重新生成）；检查报告、随机事件、路人反应不接第二遍。
- **本地时间黄牌提案自驳（不落码）**：上轮交付时助手提案「本地扫输出里的昨天/第二天亮牌」，经分析撤回——规划是前瞻文档，「第二天」大量用于合法的未来排程（现在今天、明天约会被排成「第二天」完全正确），正则分不清「把今天的事挪到明天」与「把明天的事排在明天」，落地必成误报机器；真正能做语义对账的是第二遍模型调用（已落地），加一道正则黄牌只剩噪音。

**第十三轮修订（2026-08-30 用户拍板「×2 太贵，走前缀缓存」，同节追加）**——两件落地＋两个省钱方向记录在案未采纳：

- **第二遍尾巴化（共享前缀，吃前缀缓存）**：前缀缓存（DeepSeek/Anthropic 系，命中部分约一折）按请求**开头逐字节匹配**计费。第十二轮第二遍把 system 换成「对齐审校员」提示词——前缀从第一个字节分叉，缓存一分吃不到，全量材料两遍全价。现第二遍的 messages 与第一遍**逐字节相同**（system、全部材料、联网纪要都不动），审校指令改为「## 第二遍任务：对齐审校（覆盖上文的生成任务与输出要求）」小节追加在 user 消息末尾、其后附第一遍草稿——差异越晚出现、命中的前缀越长，第二遍的新增输入只剩这条尾巴。审校清单不再复述系统提示词里已有的规则（时间顺序/事实一致性/user 不可编排/点名要求系统里都在），只留四条对账要点＋「只改违反处、校对不是重写」口径＋输出 `{plan, fixes}`；尾巴显式声明「本次不输出 checks」以覆盖 system 末尾的输出结构要求。连带受益（无需改动自动获得）：思考标头掐断重试、坏 JSON 修复重试（parseModelJson 原 messages 后追加修复对话）本就是前缀不变的重发，同样走缓存价。诚实账：**缓存只折输入不折输出**——第二遍输出（整份 plan 重发＋fixes）无折扣，×2 修正为约 ×1.2～1.4（材料越大越接近 ×1.2）；服务商不做前缀缓存时本轮改动无害也无益（第二遍输入与旧版同量级，省掉的是审校系统提示词里复述规则的那几百字、多付的是与第一遍共用的大系统提示词，两相大致抵消）。
- **材料小节重排（跨调用也吃缓存）**：排序原则＝「**开头会变的小节垫底**」——缓存前缀在第一个变化字节处断掉，其后全部按未命中计价。三股开头会变的：最近对话记录（滑动窗口取最近 N 层，每轮聊天后窗口头就变——原排第 2 位，跨次分析的缓存全灭）、检索命中的世界书（按最近楼层重扫，内容随对话变）、知识库抽样分组（轮换制每把换新）。新序：角色摘要 → 自选世界书（勾选按对话存）→ 游戏玩法（按对话存）→ 记忆表格（只追加，前缀稳定）→ 进行中剧情 → 随机事件 → 路人反应 → 历史剧情摘要（只追加）→ 近期草稿骨架 → 知识库材料 → 检索命中世界书 → 最近对话记录 → 上一版规划/修改意见/用户构思 → 联网纪要（末尾追加，不动）。剧情→事件→反应的相邻序保留；系统提示词本就声明「排列顺序不代表时间先后」，语义无迁移。检查报告（runStoryReview）同款重排。收益场景：同一对话聊几层后再分析、重新生成（按意见修订/换一版）、两遍调用——稳定小节全部命中缓存价。
- **未采纳①：第二遍砍掉知识库材料（用户提案的另一半）**——与缓存互斥：砍掉中间小节＝前缀从那里断，知识库之后的材料全部回全价；且知识库留在前缀里只花一折钱，还保住第二遍「②既定事实与设定」的核对能力（设定类清单就在知识库里）。只有服务商完全不做缓存时它才有净收益，不为它维护双路径。
- **未采纳②：第二遍无改动时只输出 fixes、不重发 plan**——输出 token 是第二遍成本大头，此法能砍掉干净草稿的整份 plan 重发；但「有 fixes 无 plan」的坏输出会降级为失败回退（现校验要求 plan 必在），两遍制刚上线未经真机验证，健壮性不换这点钱。日后真机证明第二遍输出账单刺眼时可再启。

**第十四轮修订（2026-08-30 真机反馈「第二次校验报错率奇高，经常改不出第一遍存在的问题」，同节追加）**——两处加固（均助手默认，可驳）：

- **第二遍解析接入修复梯子**：此前第二遍是裸 `extractJson`——坏格式直接整遍判失败（toast「第二遍对齐修改失败」、保留第一遍），而其它结构化流（反应卡/报告卡/导入）早有 parseModelJson 的「带修复提示回炉一次」兜底。现第二遍同款：坏 JSON 自动把「原对话＋坏输出（assistant）＋修复提示（user）」再发一次（原对话逐字节在前，前缀缓存口径不变）；修不好或「解析成功但没有可用 plan」（如模型只回 fixes 不回完整 plan——第十二轮未采纳②预言过的坏形态）仍判失败、保留第一遍，全部实报账照累计。
- **第二遍输出上限 ×1.5**：第二遍输出＝整份 plan 重发＋fixes 清单，比第一遍只长不短；同一输出上限（默认 1500）下第二遍更容易撞顶截断成坏 JSON——这是「报错率奇高」的另一半病灶。现第二遍（含修复发）按设置值 ×1.5 发（默认 1500→2250），设置 0（不限/端点默认）保持 0 不动。
- **「改不出第一遍存在的问题」不在本轮两处之内**：那属于审校效果（模型在审校位报「草稿本就全对」或改不中要害），是提示词遵循度问题非代码 bug；开关（设置页「生成后对齐修改（第二遍）」，第十二轮已有）可整体关掉只跑第一遍，审校提示词的进一步收紧待真机样本再议（改动需重审）。


### 6.12 分析运行页的状态与中断（2026-08-30 第八轮定稿并落码）

真机反馈「剧情生成途中没有中断按钮、没有运行中状态、用时、报错留存、token 计数、模型名；模型又能思考了、一万多输出」——六件一起落，分析与检查报告两页共用同一套：

- **运行状态条**：模型名（当前主连接）· 用时（0.5s 秒表）· 思考计数 · 中断键。token 实报数字在调用结束才知道（流式要等末包 usage），结束后上横幅/结果页，不在运行中虚报。
- **中断**：AbortController 从运行页一路传到 fetch（联网判断的预跑调用发出去没法掐，只能不等它）；中断后页面停在半途输出上出「已中断」横幅，去路＝再试一次（原班材料）/回第 1 步。**切聊天自动中断**在途调用（回调已被聊天令牌作废，跑完只是白花计费）。计费口径如实交代：中断前已开始/完成的调用与已生成的部分，服务商照常计费。
- **报错留存**：出错不再自动跳页＋一闪而过的 toast——报错原文（限高滚动）留在运行页横幅里，半途输出也在；修订重试失败时旧结果仍在第 3 步没动。
- **账单上页**：完成的结果页/检查报告页头部常驻一行「模型 X · 用时 Ys · 输入 A/输出 B tokens（实报）」（联网判断的调用也计入；流式没回传 usage 就如实写「无实报」）。
- **思考复发根治（两层）**：①「关闭思考」参数从两家扩到四家（deepseek/GLM 认 `thinking`、Qwen 认 `enable_thinking`、OpenAI 系认 `reasoning_effort:'none'`、vLLM 部署认 `chat_template_kwargs.thinking:false`），且端点报 400/422 时按**报错点名的参数定向去除**重发（重试梯子：全量→去点名→只留最通用的 thinking→全去；失败的 400 不产 token）——旧版一刀切全部去参重发，等于把关闭思考一起丢掉、思考静默回来，这是第八轮「关了又想了一万多」的根因（V4-Flash 思考默认开、effort 默认 high）。真被全部去掉时弹警告点名。②流式思考增量实时计数上运行条（`reasoning_content` 增量累计）——「关闭思考」开着却在涨字＝端点没执行，界面直接标⚠，用户可当场中断止损。
- **密钥小眼睛**：设置页两处密钥框（大模型/搜索）加显示/隐藏切换，只切输入框类型不动存的值（核对粘贴用）。

**第九轮修订（2026-08-30 凌晨真机反馈，同页追加）**——反馈两件：「官 key（deepseek 官方便点）怎么也复发了思考」与「流式输出每来一个字就把滚动条顶回底部，翻不上去看已输出内容」：

- **官 key 复发根因坐实（不是官方关不掉思考）**：deepseek 官方 chat/completions 正是「严格点名陌生参数」型端点（不认的字段直接 400 `Unrecognized request argument supplied: X`，宽松忽略只在另一套 Responses 端点）——旧版发的两家参数里 `enable_thinking` 是 Qwen 方言，官方一眼认出是陌生人就 400，旧版处置＝一刀切全部去参重发，把真管用的 `thinking` 一起丢了。新版四家齐发＋定向去除本就治好这条路；本轮再把重试梯子上限从三发放宽到**四发**——官方端点倾向一次 400 只点一个名，四家里的三家方言要三轮点名才去完，三发上限会在中途报错断掉（失败的 400 不产 token，多一发不花钱）。离线 9.8 例：逐个点名三轮后第四发只剩 thinking 成功。
- **流式页贴底跟随**：旧版每个流式增量都 `scrollTop = scrollHeight` 拽回底部，翻上去看旧输出根本看不成。改为**在看的人本来就在最底下（距底 <48px）时才跟随滚动，翻上去了就不动**；流式框右下角出现「回到底部」浮键（点击跳回最新并恢复跟随）；运行页刚挂载（跳走再回来）force 定位到最新输出。
- **思考原文上屏**：第八轮思考只计数（运行条「思考 N 字」），原文无处可看。现 `onReasoning` 回调改为传思考全文，流式框里带「【思考 N 字】」段头排在「【正文】」之前——计数在涨时翻上去就能核对是不是真在思考（贴底跟随修好之前想看也看不到）。

**第十四轮修订（2026-08-30 真机反馈「流式传输巨卡、两轮剧情规划能把电脑卡死」，同页追加）**——卡死根因＝上屏方式，不是网络也不是流本身：此前每个 SSE 增量（每秒可达几十次）都把「思考＋正文」**全量累计文本**整段塞回输出框的 textContent（推理模型动辄上万字的思考流，等于每拍重建几万字的文本节点）并前后各读一次 `scrollHeight`（强制同步排版）——主线程被钉死，页面与整台机器跟着卡。两改（行为与视觉不变，纯工程修复）：①**入口节流**——增量统一走 `scheduleStreamView`，约每 120ms 合成一拍上屏（挂拍期间切聊天/重开向导由令牌自然作废）；②**增量上屏**——输出框拆成稳定子节点（思考计数/思考正文/正文），新字只追加尾巴（已上屏部分不重排），新全文对不上已上屏前缀时（第二遍重开/修复重试/掐断重发）才整体换一次。贴底跟随、回到底部键、思考段头等第九轮交互原样。
- **账单行补思考字数**：结果页/报告页头部的「模型 · 用时 · …」行追加「思考 N 字」（思考过必报；「关闭思考」开着且为 0 也报「思考 0 字」）——事后查「上次到底思考没有」不用一直盯着运行条。

**第十五轮修订（2026-08-30 真机反馈「清单条目与规划输出完全不匹配」，同页追加；口径改硬的主体见 §6.9 第十五轮）**——本页两件：①**第二遍对账清单加⑤知识库口径**——第二遍尾巴在对账要点①～④后追加「⑤知识库口径：凡规划涉及某清单领域的内容选材必须来自该清单条目、第一遍自拟了的换成小节条目并同步改报 plan.knowledgeUsed；构思/修改意见点名了具体内容的以点名为准」（只在带知识材料时出现）；原「走向、节点结构、选材与 plan.knowledgeUsed 都不动」改为「走向、节点结构不动；条目选材只在违反③点名要求或⑤知识库口径时才更换」——此前第二遍的合同里选材是免检区，「该用清单而自拟」这类问题永远不纠。②**结果页「知识库选用」行**——时间基准行下方新增，模型自报的选用编号按分析时发送快照解析成「x-xx 首字段」上屏（多报/错报编号原样带出、一条没用显式点名「这算违规」）——自报此前只喂冷却结算，用户对账「模型到底说它用了哪几条」无从看起。

**第十六轮修订（2026-08-30 真机反馈「关闭思考勾着、模型仍经常思考」，用户点名要改动：不管二次校验开不开，生成内容都要在第 2 步里保留，好原样报思考标头）**——本页两件：①**运行页第一遍原文冻结保留**——此前第二遍（对齐修改）一开跑，流式框里的第一遍正文被整体顶掉（第十四轮增量上屏的「对不上前缀就整体换掉」路径），第一遍若混着思考段就再也看不到。现 `onStage('align')` 到来时把第一遍全文冻结成独立段：框内结构变为【思考 N 字】＋【第一遍生成原文 · 共 N 字】（冻结不动）＋【第二遍 · 对齐修改输出】（实时流，第二遍重开/修复重试仍只动自己这段）；跳走再回来由模块态照常重建。②**确认页②「上次生成原文」折叠区**——`run.raw` 本就是第一遍原文（第二遍对齐修改只换 `result.plan`、不动 `raw`），且已随向导快照留底（刷新/切聊天不丢），此前却没有任何展示位。现确认页「联网搜索」行下、按钮行上方加默认收起的折叠区（提示词分块同款样式），展开即第一遍原始输出全文（原样不删改，模型把思考写进正文时在这里看得到原样、可直接复制去报）。二次校验关掉时该遍就是全部输出，同样进这个折叠区。用途口径：只供人查对，不参与任何解析与重试判定。

**第十七轮修订（2026-08-30 用户反馈「这一轮关闭思考似乎真的生效了」＋点名做开关分家，同页追加）**——①**思考开关分家**：`chatCompletion` 新增按次覆盖的 `thinkingOff` 参数（缺省跟设置页总开关——生成侧九类调用行为分毫不变），**监听发调点（listenerAttempt）恒传 true**：监听每轮都跑、开了思考成本会爆炸，规划要聪明可以开思考，两侧不再共用一个开关同进退。设置页「监听」区加一行说明、总开关悬浮补「只管生成侧」、空内容报错与参数被拒 toast 的措辞改中性（不再默认用户勾过设置项——监听调用没勾任何开关也会带这些参数）。②**用户环境记账**：DeepSeek 官方 API、基本不会变（§6.5）——方言适配以官方口径为第一优先。③取证通道保留：用户约好「关闭思考开着再出现思考就把内容发来」，第十六轮「上次生成原文」折叠区就是取证位。④另立**代码地图 docs/CODE_MAP.md**（缘由＝用户指出「每次一点小改动都要阅读很久」）：文件职责、五条核心链路、「改 X 先读 Y」路由，新增文件/链路须同提交更新。
